## Conflict hot-spots (merge-with-main resolutions)
| File | Why it collides | Resolution |
|------|-----------------|------------|
| `CHANGELOG.md` | release-please appends; every branch carries its own entry | **regenerate** — let release-please rewrite it; never hand-merge |
| `.release-please-manifest.json` | every release bumps the one version | take the **higher** |
| `README.md`, `docs/` | parallel features document themselves | **union** |
| `tests/` | both sides append cases | **union** |
| `macarchy_touchbar/widgets.py` | every module wants a widget | **union** |
- **Rule of thumb:** union additive files, regenerate derived files, take-the-higher for the version;
  same-logic-both-sides is a real semantic conflict — understand both intents or stop.

## Architecture grain / invariants (shape implementation plans to these)
- The CLI client stays engine-free (~30 ms) — pinned by test_cli_client_runs_with_the_gui_libraries_blocked.
- Never hardcode a /dev/dri/cardN: the Touch Bar's number is not stable across boots.
- Renaming anything here breaks every OTHER repo shipping a module (their copies are COPIES) — re-run their install.sh.
- Hardware tests need MACARCHY_TOUCHBAR_HW_TESTS=1 and the daemon stopped (it holds DRM master).

## Environment gotchas
- This machine is an **aarch64 Asahi Linux M2 MacBook**, not a stock x86 box. Anything touching
  brightness, battery, the Touch Bar, trackpad gestures, themes or video is owned by a custom daemon.
- `git push` goes through the mise shim for its credential helper — never re-run `gh auth setup-git`.
- Two CPU clusters with a 1.58x gap (cores 0-3 = E, 4-7 = P): pin with `taskset` before timing anything.
